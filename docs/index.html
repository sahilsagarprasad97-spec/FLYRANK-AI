Abstract

Question: Can observable search-visibility and engagement signals be combined into a repeatable model that helps prioritize anonymized content items for human review?

Method: I evaluated a transparent feature-based baseline against a Random Forest regression model using observable search and engagement signals, with validation grouped by client to reduce cross-client leakage.

Result: The executed capstone notebook provides the model-versus-baseline measurements on the same held-out split; the values below should be populated directly from the final notebook outputs rather than copied from another environment.

Interpretation: The resulting ranking is treated as a decision-support signal for content review, not as evidence that any individual refresh will cause a ranking, traffic, or engagement improvement.

Use: The final action playbook converts model and visibility signals into ranked review priorities with reason codes while keeping publishing, deletion, rewriting, redirects, and other consequential actions under human control.

1. Introduction / Problem Statement

Content teams can have many pages to review, while the available search and engagement signals differ in strength and availability. The practical problem is therefore not to automatically decide what a page should become, but to create a repeatable way to prioritize which anonymized content items deserve human attention first.

This capstone supports that decision by combining observable visibility and engagement signals into a ranked review queue. The intended output is a transparent prioritization aid that can be regenerated from the warehouse rather than a one-off manual list.

Decision supported: Which anonymized content items should a reviewer inspect first, based on measured signals in the development data?

3. Methodology

Feature vector

The model uses four numeric signals: GSC impressions, GSC clicks, GSC summed position, and organic sessions. These represent observable visibility and engagement measurements available in the selected warehouse slice.

Target definition

scroll_events is treated as an observed engagement proxy. It is not interpreted as a causal measure of content quality or as proof that a future refresh will improve performance.

Baseline

The baseline is a transparent weighted ranking using 40% impressions, 40% clicks, and 20% position. It provides a simple reference point against which the model can be evaluated.

Model

A Random Forest regressor was used to model observed scroll events. The model was chosen because it can capture nonlinear relationships while remaining straightforward to inspect through feature importance.

Validation design

Evaluation uses a grouped client split. Approximately 20% of clients are held out so that pages from the same client do not appear in both the training and test sets. The model and baseline are compared on the same held-out test rows.

Leakage checks

Features derived from trends, labels, future outcomes, or other post-outcome information were excluded. The analysis also compares the model under an honest grouped split rather than relying only on a random row split.

5. Limitations & Honest Framing

  • Observational data: the analysis measures associations in recorded warehouse data and does not identify causal effects of content refreshes.
  • Development window: the primary modeling slice is March 2026, so results should not be treated as universal across all dates or clients.
  • Engagement proxy: scroll events are an observed behavior signal, not a direct measure of business value or content quality.
  • Unbalanced panel: clients have different history depth and different source availability.
  • Generalization: grouped validation reduces client overlap, but one held-out split is not equivalent to repeated external validation.
  • Missingness: unavailable analytics sources can create missing values that should not automatically be interpreted as zero performance.
Claim boundary: This paper supports measured, directional, decision-support conclusions. It does not prove Google's ranking algorithm, ranking causality, or causal refresh impact.

6. Ranked Recommendations

The final action playbook is designed to help a human reviewer decide where to look first. The ranking is a prioritization mechanism, not an automatic content editor.

01

Review high-visibility items with weaker engagement signals

Use the ranked queue to inspect pages that receive meaningful visibility but show comparatively weaker observed engagement.

02

Review visibility and click signals together

Avoid treating impressions, clicks, or position as a standalone decision. Use the combined signal profile before recommending action.

03

Use reason codes to make the queue auditable

Each recommendation should retain a human-readable reason code so reviewers can understand why an item entered the queue.

04

Keep consequential actions human-reviewed

Do not automatically publish, rewrite, delete, redirect, change URLs, or make indexing decisions from this score alone.

05

Revalidate before broad operational use

Re-run the analysis on later time windows and additional held-out clients before treating the ranking as a reusable operational signal.
